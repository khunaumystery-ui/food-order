# ระบบสั่งอาหารผ่าน QR ประจำโต๊ะ — ร้านชาบูบุฟเฟ่ต์

ลูกค้าสแกน QR ที่โต๊ะ → เลือกเมนู → ส่งออเดอร์เข้าครัวทันที
เจ้าของร้านจัดการเมนู ราคา โต๊ะ (สูงสุด **20 โต๊ะ**) และบิลได้ที่หน้า `/admin`

## เริ่มใช้งาน

ต้องมี [Node.js](https://nodejs.org) เวอร์ชัน 18 ขึ้นไป — **ไม่ต้องติดตั้งแพ็กเกจเพิ่ม**

```bash
node server.js
```

- หน้าหลังบ้าน: http://localhost:3000/admin — **เข้าได้เลยโดยไม่ต้องใส่รหัสผ่าน**
- ⚠ เมื่อนำขึ้นออนไลน์ ใครที่รู้ลิงก์ `/admin` จะแก้เมนู ราคา และปิดโต๊ะได้ ถ้าต้องการล็อก ให้ตั้งรหัสผ่านด้วย
  `ADMIN_PASSWORD=รหัสของคุณ node server.js` (PowerShell: `$env:ADMIN_PASSWORD="รหัสของคุณ"; node server.js`)
- เปลี่ยนพอร์ตด้วย `PORT=8080`

## ขั้นตอนตั้งค่าครั้งแรก

1. เข้า `/admin` → แท็บ **ตั้งค่าร้าน**: ใส่ชื่อร้าน ราคาบุฟเฟ่ต์ต่อท่าน จำนวนโต๊ะ (1–20)
   และ **ที่อยู่เว็บไซต์ของร้าน** (เช่น `https://order.ร้านของคุณ.com`)
2. แท็บ **เมนู & ราคา**: แก้ชื่อ/คำอธิบาย/ราคา ได้ทันที (ราคา 0 = รวมในบุฟเฟ่ต์, มากกว่า 0 = คิดเพิ่ม)
   ติ๊ก "พร้อมขาย" ออกเมื่อของหมด
3. แท็บ **QR Code**: กด "พิมพ์ทั้งหมด" ติดที่โต๊ะ

## การใช้งานประจำวัน

| ใคร | ทำอะไร |
|---|---|
| พนักงานต้อนรับ | แท็บ **โต๊ะ & บิล** → ใส่จำนวนลูกค้าของโต๊ะ (ระบบคิดค่าบุฟเฟ่ต์ต่อหัวให้) |
| ครัว | แท็บ **ออเดอร์** → เปิดทิ้งไว้ มีเสียงแจ้งเตือนเมื่อมีออเดอร์ใหม่ กด "เริ่มทำ" / "เสิร์ฟแล้ว" |
| แคชเชียร์ | แท็บ **โต๊ะ & บิล** → "ดูบิล / ปิดโต๊ะ" → ชำระแล้วกดปิดโต๊ะ เพื่อเริ่มบิลใหม่ให้ลูกค้ากลุ่มถัดไป |

## ความปลอดภัยของ QR

- QR แต่ละโต๊ะมีรหัสลับเฉพาะของตัวเอง ลูกค้าแก้เลขโต๊ะในลิงก์เพื่อสั่งแทนโต๊ะอื่นไม่ได้
- ถ้า QR หลุดไปนอกร้าน: แท็บ QR Code → "สร้าง QR ใหม่" (ใบเก่าใช้ไม่ได้ทันที ต้องพิมพ์ใหม่)
- ราคาคำนวณที่เซิร์ฟเวอร์เสมอ ลูกค้าแก้ราคาจากมือถือไม่ได้
- จำกัดจำนวนต่อรายการ (1–20) และกันกดส่งรัว ๆ

## นำขึ้นออนไลน์ (ให้ลูกค้าสแกนผ่านมือถือได้)

QR ต้องชี้ไปที่ที่อยู่ที่มือถือลูกค้าเข้าถึงได้ ซึ่ง `localhost` ใช้ไม่ได้ มี 2 ทาง:

1. **เช่าเซิร์ฟเวอร์/แพลตฟอร์ม** ที่รัน Node.js ได้ (เช่น Railway, Render, Fly.io, VPS) แล้วชี้โดเมนมา
   — แนะนำให้ตั้ง `ADMIN_PASSWORD` (เพราะค่าเริ่มต้นไม่มีรหัสผ่าน) และให้เก็บโฟลเดอร์ `data/` บนดิสก์ถาวร (ถ้าไม่ถาวร เมนูและออเดอร์จะหายเมื่อรีสตาร์ท)
   หรือกำหนดตำแหน่งไฟล์ด้วย `DATA_FILE=/path/to/data.json`
2. **รันที่ร้านเอง** ในเครื่องที่ต่อ Wi-Fi ร้าน แล้วให้ลูกค้าเชื่อม Wi-Fi ร้าน
   ใส่ที่อยู่เป็น IP ของเครื่อง เช่น `http://192.168.1.50:3000` ที่ช่อง "ที่อยู่เว็บไซต์ของร้าน"

ควรใช้ HTTPS เมื่อขึ้นออนไลน์ (แพลตฟอร์มส่วนใหญ่ให้อัตโนมัติ)

## โครงสร้างไฟล์

```
server.js          เซิร์ฟเวอร์ + API (ไม่มี dependency)
public/index.html  หน้าลูกค้า (มือถือ)
public/admin.html  หน้าหลังบ้าน
public/qr.js       ตัวสร้าง QR (MIT, ดูหัวไฟล์)
data/data.json     ข้อมูลทั้งหมด (สร้างอัตโนมัติ) — สำรองไฟล์นี้ไฟล์เดียวพอ
```

## ข้อจำกัดที่ควรรู้

- เหมาะกับร้านเดียวที่ใช้เซิร์ฟเวอร์เครื่องเดียว (เก็บข้อมูลเป็นไฟล์ JSON)
- หน้าหลังบ้านอัปเดตออเดอร์ทุก 5 วินาที (ไม่ใช่ real-time ทันที)
- ยังไม่มีรูปภาพเมนู, ระบบชำระเงินออนไลน์ หรือเชื่อมเครื่องพิมพ์ใบสั่งครัว
